# Binary Search Tree (BST) -- Introduction

## 1. Topic / Definition

A **Binary Search Tree (BST)** is a binary tree that follows an ordering
rule:

-   Every value in the **left subtree** of a node is smaller than that
    node's value.
-   Every value in the **right subtree** of a node is greater than that
    node's value.
-   The left and right subtrees must themselves also be BSTs.

In the standard definition of BST, duplicate values are
not allowed.

### Binary Tree vs Binary Search Tree

-   **Binary Tree:** Each node can have at most two children. There is
    no required ordering between the values of the left and right
    children.
-   **Binary Search Tree:** It is a binary tree with an additional
    ordering property: smaller values go to the left and greater values
    go to the right.

------------------------------------------------------------------------

## 2. BST Properties and Example

Consider this tree:

``` text
             8
           /   \
          3     10
         / \      \
        1   6      14
           / \     /
          4   7   13
```

Why is it a BST?

-   For root `8`, every value in its left subtree (`3, 1, 6, 4, 7`) is
    smaller than `8`.
-   Every value in its right subtree (`10, 14, 13`) is greater than `8`.
-   The left subtree rooted at `3` is also a BST:
    -   `1 < 3`
    -   `6 > 3`
    -   Within the subtree rooted at `6`, `4 < 6` and `7 > 6`.
-   The right subtree rooted at `10` is also a BST:
    -   `14 > 10`
    -   `13 < 14`

**Important:** It is not enough to check only the immediate left and
right children. The ordering rule applies to **all nodes in each
subtree**.

------------------------------------------------------------------------

## 3. Duplicate Values in a BST

According to the lecture, the standard assumption is that duplicates are
**not allowed**.

If an implementation needs to support duplicates, the lecture describes
two possible approaches:

### Approach 1: Choose a consistent side for duplicates

Modify the ordering rule so that equal values are allowed on one fixed
side.

For example:

-   Left subtree: values less than or equal to the node.
-   Right subtree: values greater than the node.

The opposite convention can also be chosen, but the rule must be applied
consistently.

### Approach 2: Store a frequency

Keep one node for a value and store how many times that value occurs.i.e store value,freq in every node itself

For example:

``` text
Value: 8
Frequency: 2
```

This represents two occurrences of the value `8` without creating two
separate nodes.

------------------------------------------------------------------------

## 4. Why Use a Binary Search Tree?

A normal binary tree does not provide an ordering rule. To search for a
value, we may need to visit many or all nodes.

A BST uses its ordering property to decide which subtree can contain the
target.

Example: Search for `6` in the tree above.

``` text
             8
           /   \
          3     10
         / \      \
        1   6      14
           / \
          4   7
```

Search steps:

1.  Start at `8`. Since `6 < 8`, move left.
2.  Reach `3`. Since `6 > 3`, move right.
3.  Reach `6`. The value is found.

At each node, we eliminate the subtree that cannot contain the target.
This is similar to the decision process used in Binary Search.

------------------------------------------------------------------------

## 5. Height of a BST and Search Complexity

The number of nodes visited during a BST search depends on the tree's
height.

### Balanced BST

When the tree is reasonably balanced, its height is approximately
`O(log n)`.

-   Search: `O(log n)`
-   The tree's ordering property lets us discard one side at each step.

### Degenerate / Skewed Tree

A BST can become skewed if values are in ascending/descending order.

Example:

``` text
    1
     \
      2
       \
        3
         \
          4
           \
            5
```

This behaves like a linked list.

-   Height: `O(n)`
-   Search: `O(n)`

**Important clarification:** A BST is not automatically balanced. Its
search operation is `O(h)`, where `h` is the height of the tree.
Therefore:

-   Balanced BST: typically `O(log n)` search.
-   Skewed BST: worst-case `O(n)` search.

Self-balancing BSTs are designed to keep the height logarithmic.

## 7. Key Observations / Interview Points

1.  A BST is a **binary tree with an ordering property**.
2.  Every value in the left subtree must be smaller than the current
    node.
3.  Every value in the right subtree must be greater than the current
    node.
4.  Both left and right subtrees must independently satisfy the BST
    property.
5.  Checking only the immediate children is insufficient; the rule
    applies to the entire subtrees.
6.  The standard convention in this lecture is that duplicates are not
    allowed.
7.  If duplicates are required, either define a consistent rule for
    which side can contain equal values or store a frequency in each
    node.
8.  BST search follows one path by comparing the target with the current
    node.
9.  Search complexity is `O(h)`, where `h` is the tree height.
10. A balanced BST can support `O(log n)` search, while a skewed BST can
    take `O(n)`.
