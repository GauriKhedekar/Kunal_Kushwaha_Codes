### 🟢 New Problem Template
- 1. Understand — 2–3 min

Write/say:

Given: What is the input?
Need: What exactly is asked?
Constraints: What are the limits?
Example: Can I explain it in my own words?


- 2. Think Before Coding — 5–10 min

Ask yourself:

What is the brute force?
What is making brute force slow?
Does this look like a known pattern?
Can I improve using a data structure / observation?


- 3. Solve — 15–30 min
Explain your approach out loud
Write pseudocode mentally/on paper
Code without looking at the solution
Dry-run on:
normal case
edge case
smallest case


- 4. Complexity

Always state:

Time: O(...)
Space: O(...)


- 5. If Stuck

Don't immediately see the solution.

Use this order:

Think → small hint → think again → second hint → solution

After seeing the solution:

Close it.
Explain the idea yourself.
Code it again without copying.
Ask: “What was the key observation I missed?”


### 🔵 Recall Template

- For every previously solved problem, don't reread the whole solution first.

- Look only at the problem name and answer:

Problem:
Pattern:

- 1. Key observation:
- 2. Approach:
- 3. Why does it work?
- 4. Time:
- 5. Space:
- 6. Edge cases:
- 7. Can I code it without looking? YES / NO

If YES → move on.

If NO → look at your notes/solution briefly → close them → explain/code again.

#### Recall schedule

- Day 1  → Explain approach
- Day 3  → Explain approach
- Day 7  → Code without looking
- Day 14 → Explain like an interview
- Day 30 → Quick recall

  
#### 🚫 What NOT to Do With ChatGPT
Don't:

❌ Ask: “Solve this problem.” immediately
❌ Read the complete solution before trying
❌ Copy-paste ChatGPT code
❌ Ask for optimized code before understanding brute force
❌ Keep asking ChatGPT to explain every line
❌ Consider a problem “done” just because you understood the explanation
❌ Re-read solutions repeatedly instead of recalling
❌ Spend 1 hour stuck on one problem

- Instead, use ChatGPT like an interviewer:

If stuck:

“I'm solving this myself. Don't give me the solution. Give me only one small hint.”

If you have an approach:

“Here is my approach. Don't solve it. Tell me only whether my reasoning is correct and point out the flaw if there is one.”

For implementation:

“I understand the algorithm but I'm struggling to implement it in Java. Don't give complete code. Tell me what syntax/data structure/API I need.”

For interview practice:

“Interview me on this problem. Don't give hints unless I ask.”


#### ⭐ Your Golden Rule

Understanding a solution ≠ solving a problem.

You should be able to:

Understand → Think → Explain → Code → Dry Run → Recall

If you can do those without looking, count it as truly solved.
